# 함께 읽는 방 · 리뷰 시연 (PDF 공동 리뷰 개념 프로토타입)

한 문서 위에, 서로의 관점을. 신청서 PDF를 읽으며 문장을 하이라이트하고, 예시 댓글을 연결하고, 내 점수를 남기는 **리뷰어 작업 화면 1개**를 브라우저 로컬에서 시연합니다. 흑백 · 얇은 테두리 · IBM Plex Sans KR 기준의 편집 작업 공간이며 마케팅 랜딩이 아닙니다.

## 실행

```
python -m http.server 8794
```

그 뒤 `http://localhost:8794/index.html` 을 엽니다. 모듈(`type="module"`)과 pdf.js 워커 때문에 `file://` 로 직접 열면 PDF가 로드되지 않으며, 화면에 오류 문구가 표시됩니다.

```
npm test
```

`node --test tests/*.test.mjs` 로 기하 · 점수 · 댓글 검증 · 탭 · 상태 단위 테스트와 구조 계약 테스트를 실행합니다. 단위 테스트는 브라우저 선택·확대 동작을 검증하지 않습니다. 실제 드래그 선택, 확대/리사이즈 후 정렬, 모바일 배치는 `tests/browser-qa.md` 의 점검표대로 브라우저에서 별도로 확인해야 합니다.

## 실제로 구현된 것

- **실제 PDF 렌더**: `vendor/pdf.mjs`(pdf.js) 로 `assets/sample-application.pdf`(자작 2쪽, 선택 가능한 한글 텍스트) 를 canvas 에 그리고, pdf.js `TextLayer` 로 실제 텍스트 레이어를 올립니다. HTML/이미지로 PDF 를 흉내 내지 않습니다.
- **글자 하이라이트**: 텍스트 레이어를 드래그 선택 → `선택 문장 하이라이트`. `Range.getClientRects()` 를 현재 쪽 영역으로 자른 뒤 `viewport.convertToPdfPoint` 로 **확대율 무관 PDF 좌표**로 저장합니다(쪽 번호 + 사각형 목록 + 선택 원문 + 가상 작성자 + ID). 표시할 때마다 `convertToViewportRectangle` 로 다시 계산하므로 확대 · 쪽 이동 · 창 크기 변경 뒤에도 CSS 픽셀을 저장하지 않습니다.
- **여백에서 시작·끝나는 드래그**: pdf.js 상류(`TextLayerBuilder`)의 전역 selection 처리(`.selecting` 중 `.endOfContent` 를 앵커 span 뒤로 옮겨 레이어를 덮는 방식)를 단일 뷰어용으로 옮겼습니다. 여기에 더해 마우스 드래그는 `pointerdown` 에서 `caretRangeFromPoint`(없으면 가장 가까운 줄의 끝 글자)로 **실제 텍스트 노드 위치**를 찾아 `Selection.setBaseAndExtent/extend` 로 선택합니다. 글자 줄 밖 5px 에서 시작하거나 끝나도 그 줄이 선택되며, 여백→여백 한 줄 드래그와 여러 줄 드래그가 됩니다. 터치 · 키보드 · 더블클릭 · Shift+클릭은 브라우저 기본 선택을 그대로 둡니다. 버튼을 누르는 사이 선택이 풀리면 `selectionchange` 에서 보관한 마지막 실제 `Range` 로 확정합니다.
- **보조 선택 경로**: `예시 문장 선택` 은 실제 텍스트 레이어의 span 안에서 '열린 책상' 구간을 `Range` 로 선택만 합니다. 하이라이트는 사용자가 다시 `선택 문장 하이라이트` 를 눌러야 만들어집니다(키보드 · 터치 보조용, 가짜 텍스트 아님).
- **표식**: 하이라이트마다 작성자 초성 `가` 표식 버튼(44px 탭 영역, 22px 라벨)을 **쪽 오른쪽 여백(gutter 56px, PDF 스크롤 영역 안에 예약)** 에 두고 점선으로 하이라이트와 잇습니다. 어떤 확대율에서도 본문 글자를 덮지 않으며, 같은 줄의 표식은 아래로 비킵니다. 색만으로 구분하지 않습니다. 오버레이는 `pointer-events: none` 이라 다른 글자 선택을 막지 않습니다.
- **하이라이트 ↔ 댓글 왕복**: 표식을 누르면 연결된 댓글로 포커스가 이동하고, 댓글이 없으면 새 이야기 패널로 이동하며 상태 문구(화면 낭독기용 `role=status`)로 알립니다. 댓글 카드를 누르면 해당 쪽 · 위치로 이동하고 선택 상태(두꺼운 테두리)로 표시합니다.
- **댓글 · 답글(자유 입력, 로컬)**: 새 이야기 textarea(최대 500자, 공백만은 거부, `core.mjs` 와 UI 양쪽에서 검사)에 직접 쓰고 ①②③ 이야기 꼭지 체크박스를 고른 뒤 `남기기`. 두 예문 버튼은 textarea 를 채우기만 하며 고쳐 쓸 수 있습니다. 선택한 하이라이트 또는 신청서 전체에 연결. 댓글 본문·꼭지와 답글은 카드 안 인라인 폼으로 **수정**할 수 있고(하이라이트 연결은 유지), 답글은 **1단계까지만**. 본문은 `textContent` 로만 표시하므로 스크립트 문자열도 글자로 보입니다. 작성자는 `리뷰어 A(가상)` · `리뷰어 B(가상)` 로 고정이며 이름 · 연락처 등 개인정보 입력란은 없습니다. 전송 · 저장 없음, 새로고침 시 사라집니다.
- **이야기 탭**: `함께 나눈 이야기 N` / `이 쪽(Np)만 N` 두 탭(검정 활성). 쪽을 넘기면 라벨과 수가 다시 계산되고, 전체 문서 댓글은 쪽 탭에 나오지 않습니다.
- **보기 필터**: 모든 하이라이트 / 내 것만(단일 사용자라 전체와 동일) / 숨기기. 숨겨도 메모리는 지워지지 않고, 댓글에서 위치로 이동하면 다시 표시됩니다.
- **배치**: 1100px 초과에서는 PDF(왼쪽) · 이야기(오른쪽, 최소 500px = 44px 점수 버튼 10개 한 줄) 2열이고 도구줄은 한 줄입니다(1440 기준 PDF 약 65%). 1100px 이하에서는 PDF → 이야기 → 내 점수 순으로 쌓입니다. 600px 이하에서는 하이라이트 도구가 `<details>` 로 접히고 쪽 이동 · 확대 · 맞춤만 보이며, 쪽은 **1:1 이상** 으로 그려 본문이 12px 아래로 내려가지 않고 PDF 영역 안에서만 가로 스크롤합니다(`맞춤` 으로 화면 너비 맞춤 전환).
- **내 점수**: 1~10 정수 버튼(`aria-pressed`), 0 · 소수 없음, 미선택은 별도 상태. `검토 완료(시연)` 는 점수 선택 후에만 활성화되며 로컬 상태만 바꿉니다.
- **운영진 집계 개념**: 리뷰 화면 밖의 `<details>` 안에 **정지된 가상 집계 표**만 둡니다. 내 점수와 연동되지 않으며 다른 사람 점수는 리뷰 화면 어디에도 나오지 않습니다.
- **오류 경계**: PDF 로드 실패 · 선택 없음 · 쪽 밖 선택 등은 빈 화면 대신 `role="alert"` 영역과 상태 문구로 표시됩니다.

| 리뷰어(친구) | 하이라이트 · 예시 댓글 · 내 점수(로컬) | 로그인 · 초대 코드 · 본인 데이터만 수정/삭제 · 다른 사람 점수 차단 |

다음은 **이 시연에서 구현하지 않았습니다**(실제 서비스 범위이지만 여기 없음): 백엔드 · 인증 · 행 수준 권한(RLS) · 공동 동기화 · 업로드 · 원본 PDF 다운로드 · 메일 · 데이터 내보내기 · 영구 저장(localStorage 포함) · 자동 파기 · **이해관계 제외 버튼**(1차 범위 기능이지만 서버 권한이 필요해 미구현) · 목록으로 돌아가기 · 이전/다음 신청서 이동 · 한 줄 총평. 영역(이미지) 하이라이트는 고객 측 2차 범위이며 역시 없습니다. 화면에는 작동하는 척하는 컨트롤을 두지 않았고, 제외 목록은 화면 맨 아래 `<details>` 에만 적었습니다. 모든 상태는 JS 메모리에 있으며 **새로고침하면 초기화**됩니다. 외부 네트워크 요청(CDN · 폰트 · 분석) · `fetch` · 저장소 호출은 없습니다. PDF 라이브러리는 로컬 복사한 pdf.js 뿐입니다.

## 알려진 한계 · 확인이 필요한 점

- 스캔본처럼 텍스트가 없는 PDF 는 이 시연에서 하이라이트할 수 없습니다(영역 하이라이트 미구현). 샘플은 텍스트가 있는 자작 PDF 입니다.
- 텍스트 레이어 정렬은 pdf.js 의 `--total-scale-factor` CSS 변수에 의존합니다. 핵심 규칙을 `style.css` 로 옮겼으며, 브라우저별 선택 하이라이트 정렬은 실기기에서 확인해야 합니다.
- 150% 확대 시 좁은 화면에서는 PDF 영역 안에서만 가로 스크롤이 생기고 도구줄은 잘리지 않도록 했습니다. 실제 320/390px 확인은 별도 브라우저 검증 대상입니다.
- 모바일(≤600px) 기본은 1:1 배율이라 **줄마다 가로로 이동해 읽어야 할 수 있고**, 쪽 오른쪽의 표식 거터가 화면 밖에 있을 수 있습니다. `맞춤` 은 쪽 전체를 보여 주지만 글자가 작아집니다. PDF 본문을 화면 폭에 맞춰 다시 흘리는(리플로우) 기능은 없습니다. 도구줄 아래 한 줄 안내(`가로로 이동해 읽기 · 전체 보기는 맞춤`)는 600px 이하에서만 보입니다.
- 표식 연결 점선은 쪽(종이) 바깥 거터 8px 구간에만 그립니다. 본문 글자 위에는 어떤 선도 긋지 않습니다.

## 실제 화면에서 보완한 선택 정렬

- PDF.js 텍스트 레이어의 파생 배율(`--total-scale-factor`)을 각 PDF 페이지에 설정합니다. 루트의 1배 값을 상속하면 모바일에서 선택 영역이 어긋날 수 있습니다.
- 이 시연은 동봉된 자작 PDF 한 종류만 지원합니다. PDF와 같은 로컬 IBM Plex Sans KR의 글리프 폭으로 선택 텍스트를 배치합니다. 임의 업로드 PDF의 모든 글꼴·스캔 문서 지원을 뜻하지 않습니다.
- 좌표 기준은 테두리를 포함하는 바깥 패널이 아니라 실제 canvas 경계입니다. 320/390/768/1024/1366/1440에서 실제 문장 선택(여백 시작·끝 포함)·확대·쪽 이동·댓글 연결·표식 비겹침을 Chromium 에서 점검했고 확대/축소 후 하이라이트와 글자 줄의 차이는 2px 안이었습니다. Firefox · Safari · 실기기 터치는 `tests/browser-qa.md` 로 별도 확인이 필요하며, 서버 권한/공동 동기화 검증을 대신하지 않습니다.
- 320px 에서는 도구줄이 두 줄이 됩니다(390px 부터 한 줄).
